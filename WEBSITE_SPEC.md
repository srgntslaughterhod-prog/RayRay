# WEBSITE_SPEC

Status: DRAFT FOR IMPLEMENTATION

---

# Purpose

The RayRay website introduces visitors to RayRay and tells RayRay's story.

The website should feel like an illustrated character story combined with a clean, modern crypto project page.

The website should not feel like an aggressive token-sales page.

Primary rule:

> **The visitor should meet RayRay before the visitor meets $RAYRAY.**

---

# Website Goals

The website should:

1. Introduce RayRay immediately.
2. Make the character understandable without requiring crypto knowledge.
3. Tell RayRay's lifecycle visually.
4. Show the project's actual current state.
5. Give the community a place to follow the adventure.
6. Provide official token information when available.
7. Provide official social and trading links without aggressive calls to buy.
8. Remain simple enough to maintain with minimal ongoing development.

---

# Design Direction

Use the canonical RayRay visual identity defined in `VISUAL_BIBLE.md`.

Overall feel:

- friendly;
- polished;
- slightly whimsical;
- space-oriented;
- illustrated;
- warm;
- modern;
- uncluttered;
- easy to navigate;
- mobile friendly.

The website may be playful.

The website should not be childish.

RayRay's Solana-inspired color palette should drive accents, lighting, buttons, section transitions, and interactive elements.

Use generous space around artwork.

Let RayRay be the visual focus.

---

Graduation happens only if the token actually satisfies the selected launch platform's Graduation requirements.

It does not automatically mean Blast Off occurs.

# 5. Graduation

Explain Graduation simply.

Avoid unnecessary bonding-curve mathematics on the primary story page.

Core idea:

> RayRay doesn't receive the Astronaut helmet because a roadmap says so.
>
> RayRay has to Graduate.

The actual launch venue, Graduation target, liquidity mechanics, and official trading information should be displayed factually once finalized.

No fake Graduation date.

No fake countdown.

No implication that Graduation is guaranteed.

# 7. THE MOON

THE MOON remains intentionally undefined.

Do not associate THE MOON with:

- a specific token price;
- a specific market capitalization;
- a deadline;
- guaranteed appreciation;
- or a promised financial result.

THE MOON is RayRay's impossible-looking destination.

Everyone else keeps asking:

> **WEN MOON, RAY?**

RayRay's answer may simply be:

> *Someday...*

---

# 8. Token Information

Token information should be useful, factual, and understated.

Before launch:

**$RAYRAY**

Status:

**Pre-Launch**

After launch, provide:

- official token name;
- official ticker;
- network;
- official mint address;
- launch venue;
- current lifecycle stage;
- Graduation status;
- post-Graduation venue if applicable;
- official market/trading link;
- liquidity information when relevant and verified.

The mint address should be easily copyable.

Clearly label the official mint address to help visitors distinguish RayRay from copycats.

Do not use:

- giant BUY buttons;
- flashing trading CTAs;
- fake urgency;
- countdown timers;
- "100X" language;
- price predictions;
- guaranteed-return language.

People who want to trade RayRay should be able to find the legitimate venue easily.

They should not be pressured to do so.

# Technical Scope

Version 1 should be a lightweight static website.

Preferred characteristics:

- responsive;
- fast loading;
- mobile first;
- accessible;
- easy to maintain;
- minimal dependencies;
- minimal JavaScript;
- no unnecessary backend;
- no wallet connection required for the initial website;
- no trading functionality implemented directly by RayRay;
- external trading links only after launch.

Use the existing repository and GitHub workflow.

Do not introduce infrastructure unless the website actually needs it.

> RAYRAY IS BORN

During growth:

> GROWING

> BUILDING

The project determines the story.

The story does not determine the project.

---

# Primary Website Rule

> **RayRay's story never outruns RayRay's reality.**

If RayRay remains on the bonding curve, RayRay remains in the pre-Graduation story.

If RayRay does not Graduate, RayRay does not receive a fictional Graduation.

If RayRay Graduates but there is no reason to Blast Off, RayRay remains an Astronaut on Planet Solana.

That is okay.

---

# Scope Rule

Do not turn the website into another protocol.

If a feature does not help visitors:

- meet RayRay;
- understand RayRay;
- follow RayRay;
- verify RayRay;
- or join RayRay's community;

it probably does not belong in version 1.

---

# Final Experience

A visitor should leave the website understanding:

1. Who RayRay is.
2. What RayRay dreams about.
3. What RayRay is actually doing right now.
4. Where to follow RayRay.
5. How to verify the real $RAYRAY token once launched.

The desired reaction is not:

> "I need to buy this immediately."

The desired reaction is:

> *"Okay... I kind of want to see if this little guy makes it."*
